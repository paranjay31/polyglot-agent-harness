# Version 0.1.2

Security and reliability fixes from the adversarial review:

- Reject Git option injection through the read-only `git_show` tool and disable external diff/text conversion for read-only diffs.
- Hash verification definitions, wrappers, and lockfiles. Changed definitions require approval and are checked again after authorization. Local repository commands require approval even in auto mode.
- Require operator-pinned repository configuration before starting MCP or LSP processes, attaching repositories, or applying sandbox settings and permission overrides.
- Execute remote commands in a container scoped to one workspace, without network or host environment inheritance, with resource limits and a read-only root filesystem.
- Propagate cancellation to model requests, verification, delegated runs, command process groups, and remote workers. Confirm container cleanup; uncertain termination fails the run and retains workspace ownership for operator inspection.
- Preserve executable permissions when replacing existing files.
- Report unverified changes separately from successful completion and preserve runtime outcomes in HTTP background and streaming responses.
- Reject active session collisions and concurrent access to the same workspace; never evict active background runs. CLI, server, and ACP runs acquire cross-process workspace leases.
- Show complete action arguments, workspace, risk, and proposed edit content in approval prompts.

## Migration

Review `.agent/config.json`, run `agent config-digest --workspace /path/to/repo`, and pin the resulting value in the operator's `AGENT_TRUSTED_CONFIG_SHA256` launch environment when using the features listed above. Configuration changes or moving the workspace require a new pin. Do not regenerate it automatically from repository-controlled scripts.

Local test/build execution now needs interactive approval. For unattended execution, use an isolated sandbox and unchanged verification definitions. Remote workers require Docker or Podman; configure `AGENT_REMOTE_RUNTIME` and `AGENT_REMOTE_IMAGE` on the worker host. See the updated deployment guide in `deploy/remote-worker/README.md` in the source repository.

Consumers of background-run statuses must handle `cancelling` and `unverified`. Terminal SSE events now reflect the actual outcome (`completed`, `unverified`, `failed`, or `cancelled`).

## Validation

The TypeScript build and 97 tests passed with real Docker tests enabled. Coverage includes workspace confinement, cancellation, atomic file permissions, mutable verification definitions, configuration trust, and HTTP lifecycle handling. The opt-in real-model-provider test was not run.
